Let me break this down systematically. ## Core Networking Principles Kubernetes follows these key networking rules: - **Every pod gets its own IP address** - no need for port mapping - **Pods can communicate with each other** without NAT across nodes - **Agents on nodes can communicate with all pods** on that node - **Flat network space** - all pods exist in the same network namespace ## Key Networking Components ### 1. Pod Networking ```yaml # Each pod gets an IP from the cluster CIDR apiVersion: v1 kind: Pod metadata: name: my-pod spec: containers: - name: app image: nginx ports: - containerPort: 80 ``` - Pods within the same node share the node's network namespace - Containers in a pod share the same IP and can communicate via localhost - Pod IPs are ephemeral and change when pods are recreated ### 2. Services Services provide stable networking for dynamic pod environments: ```yaml apiVersion: v1 kind: Service metadata: name: my-service spec: selector: app: my-app ports: - port: 80 targetPort: 8080 type: ClusterIP # Default type ``` **Service Types:** - **ClusterIP**: Internal cluster communication only - **NodePort**: Exposes service on each node's IP at a static port - **LoadBalancer**: Provisions external load balancer (cloud provider) - **ExternalName**: Maps service to external DNS name ### 3. Container Network Interface (CNI) CNI plugins handle the actual network implementation: **Popular CNI plugins:** - **Flannel**: Simple overlay network using VXLAN - **Calico**: Layer 3 networking with network policies - **Weave**: Mesh networking with encryption - **Cilium**: eBPF-based networking with advanced features ## Network Flow Examples ### Pod-to-Pod Communication (Same Node) ``` Pod A (10.244.1.10) → Virtual Bridge → Pod B (10.244.1.11) ``` ### Pod-to-Pod Communication (Different Nodes) ``` Pod A (10.244.1.10) → Node 1 → Overlay Network → Node 2 → Pod B (10.244.2.10) ``` ### Service Discovery ```yaml # Service creates endpoints apiVersion: v1 kind: Service metadata: name: database spec: selector: app: db ports: - port: 5432 --- # Pods can reach service by name apiVersion: v1 kind: Pod spec: containers: - name: app env: - name: DB_HOST value: "database" # Resolves to service IP ``` ## Advanced Networking Concepts ### 1.
